# Phase 5 — Manual test guide and migration notes

Covers [phase-5-powerplatform-integration](../phase-5-powerplatform-integration): linking Power Platform solutions to epics (Dev, Test, Stage, Prod) and checking a story's solution version against a stage.
Run `npm test` first (142 tests, including `phase5-domain` and `phase5-service`). This guide covers UI behaviour, permissions, the connectors and the hosted environment.

## Migration from Phase 4

For environments already running Phase 4 (Platform-Tools was migrated on 2026-10-21):

1. **Schema (done for Platform-Tools).** New table **Epic Solution** (`wd_epicsolution`) and a new Issue column **Solution Version** (`wd_solutionversion`). Both start empty; no back-fill.
2. **Connections (done for Platform-Tools).** Connection references for **Power Platform for Admins V2** and **Microsoft Dataverse** are in `power.config.json`, and their wrappers are in `dist/connectors/` (generated by CAP from connected connections). Users consent to both on first launch ([dataverse-setup.md](dataverse-setup.md) §4b).
3. **Security role.** Add Epic Solution to **Pira User** (Create/Read/Write/Append Org, **no Delete**), §1.
4. **Alternate key.** Epic Solution (Issue + Stage), §2.
5. **Plug-ins.** Create **37–39** ([lowcode-plugins.md](lowcode-plugins.md)). Done on Platform-Tools.
6. **Feature flag.** `FEATURES.powerPlatform` in [`dist/config/app-config.js`](../dist/config/app-config.js). Off hides the Solutions and Solution version sections and the data service refuses the calls.
7. **Rollback.** Everything is additive. Turn the flag off or redeploy the Phase 4 build. Turn off plug-ins 37–39 to stop the server-side checks.

## 2. Epic solutions

| # | Steps | Expected |
|---|---|---|
| E1 | Open an epic | A **Solutions** section with four rows: Dev, Test, Stage, Prod. Linked rows show the solution name (a link), schema name, environment, **live version** and **modified date**. |
| E2 | Click a solution name | make.powerapps.com opens in a new tab on that solution in that environment. |
| E3 | Stage row → **+ Link solution** | Dialog with a searchable **Environment** picker (lists on focus; filter by name, type or host). Only environments with Dataverse appear. |
| E4 | Pick an environment | A searchable **Solution** picker appears (visible solutions, display or schema name). |
| E5 | Link Stage after Test is linked (mock: pick Contoso Stage) | *PiraCore* is selected automatically: "same schema name as the Test solution". Save → Stage row shows v1.2.0.0. |
| E6 | Link Prod and pick an environment without that schema name (mock: Team Sandbox) | "No solution with the schema name … Pick one below." Nothing is pre-selected. |
| E7 | **Change** a linked stage, pick another solution | The row is replaced (no duplicate row); history shows "changed the Dev solution A → B". |
| E8 | **Unlink** a stage, confirm | The row shows "No solution linked"; history shows "… → None". The row stays in Dataverse with empty fields (no delete). |
| E9 | **Refresh versions** after changing the solution version in the environment | The new version and modified date appear; "was vX when linked" shows the snapshot. |

## 4. Server-side and security (hosted)

| # | Steps | Expected |
|---|---|---|
| P1 | Web API: create an Epic Solution for a Task, or a second row for the same epic + stage | `[INVALID_EPIC_SOLUTION]`, rolled back (plug-in 37; the alternate key also blocks the duplicate). |
| P2 | Web API: PATCH an Epic Solution's URL to `https://evil.example`, or its stage | `[INVALID_EPIC_SOLUTION]`. |
| P3 | Web API as a stakeholder: link or unlink | `[PROJECT_ACCESS_DENIED]`. |
| P4 | Web API: PATCH an issue's Solution Version to `abc` (story) / `1.0` (task) | `[INVALID_SOLUTION_VERSION]` / saved as blank. |
| P5 | Any normal issue edit (summary, status, drag on board) | Still saves — plug-in 39 runs on every issue update. |
| P6 | Edit an Epic Solution row so its URL points at another host, then open the epic | The app refuses to call it ("Choose an environment that has Dataverse") and never builds a link to it. |
| P7 | Browser dev tools: call `linkEpicSolution` with an environment id/URL pair that isn't in your environment list | Refused before any write; the stored version always comes from the environment, not the browser. |
